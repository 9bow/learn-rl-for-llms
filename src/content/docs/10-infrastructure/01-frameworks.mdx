## 프레임워크와 알고리즘의 구분

프레임워크는 정책·롤아웃·보상·분산 학습을 조율한다. PPO·GRPO·DPO는 그 안에서 구현하는 알고리즘이다. 같은 이름의 알고리즘도 보상 정규화·토큰 집계·비동기 보정이 다를 수 있다.

이 장의 현재 지원 범위는 2026년 10월 23일 공식 저장소·릴리스 기준이다. 실제 재현에는 릴리스와 모델·추론 엔진·CUDA·PyTorch 조합을 함께 고정해야 한다.

## OpenRLHF

[OpenRLHF](https://github.com/OpenRLHF/OpenRLHF)는 Ray로 작업을 조율하고 vLLM 롤아웃과 DeepSpeed 학습을 통합한다. 원 프레임워크 논문은 `arXiv:2405.11143`이며, `2501.03262`는 REINFORCE++ 논문이다.

현재 저장소는 단일 턴·멀티턴 실행기를 공유하는 agent 기반 구조를 설명한다. PPO, REINFORCE++, GRPO, RLOO 등의 advantage 계산을 실행 모드와 분리한다. VLM 지원은 알고리즘 이름이 아니라 모델·입력 지원 기능이다.

2026년 4월의 0.10 발표는 이미지 입력과 환경 피드백을 포함하는 멀티턴 VLM RL을 추가한다. 9월 발표는 critic 없이 프롬프트당 한 롤아웃을 사용하는 비동기 FlashREINFORCE 구성과 예제를 제시한다. 어느 방법이든 전체 학습 조건을 보지 않고 "항상 가장 효율적"이라고 판단하지 않는다.

현재 예제의 구성 키는 `--algo.advantage.estimator`, `--train.async_enable`, `--train.agent_func_path`처럼 분리되어 있다. 과거의 짧은 플래그 예제를 현재 버전과 혼합하지 않는다. 역할별 GPU 분리는 가능한 배치이며 모든 구성이 독립 GPU 그룹을 요구하지는 않는다.

## verl과 HybridFlow

공식 저장소는 현재 [verl-project/verl](https://github.com/verl-project/verl)이다. 기존 `volcengine/verl` 주소는 이동된다. HybridFlow는 전체 제어 흐름과 모델 내부 분산 계산을 분리하는 설계다.

[v0.9.1 릴리스](https://github.com/verl-project/verl/releases/tag/v0.9.1)는 통합 V1 trainer와 동기·비동기 실행을 다룬다. DAPO의 유효 그룹 필터, 생성·학습 분리, 체크포인트 확장 지점을 포함한다. 이전 실험용 fully-async 경로와 현재 통합 trainer를 같은 API로 취급하지 않는다.

실제로 사용할 알고리즘·모델의 공식 예제를 먼저 선택한다. FSDP·Megatron 백엔드, VLM·도구 입력 지원, vLLM·SGLang 버전은 예제와 릴리스의 조합을 따른다. 과거 표의 "VLM 제한적"이라는 고정 평가로 현재 지원을 판단할 수 없다.

## TRL

[TRL](https://github.com/huggingface/trl)은 Hugging Face 모델·데이터·Accelerate와 결합한 트레이너를 제공한다. 현재 주 트레이너에는 SFT, DPO, GRPO, KTO, Reward, RLOO, Distillation 등이 있다.

[v1.13.0](https://github.com/huggingface/trl/releases/tag/v1.13.0)은 PPO와 value-head 코드·문서·예제의 제거를 명시한다. [PR #7020](https://github.com/huggingface/trl/pull/7020)이 이 변경이며, 루트 `from trl import PPOTrainer`는 이미 v1.10에서 실험 경로로 이동했다. [v1.14.0](https://github.com/huggingface/trl/releases/tag/v1.14.0)은 실험용 PRM·BCO·GSPO-token 등의 제거를 별도로 명시한다. 현재 확인한 v1.16.0에도 PPO 구현은 없으며, [해당 태그의 루트 export](https://github.com/huggingface/trl/blob/v1.16.0/trl/__init__.py)에도 PPOTrainer가 없다. 검색된 과거 문서만으로 현재 API가 남아 있다고 판단하지 않는다.

GRPO는 현재 기본 손실 `dapo`와 기본 `beta=0.0`을 사용한다. 원 논문의 목적식을 재현하려면 손실 집계·보상 스케일링·KL·클리핑을 명시한다. 실험용 비동기 트레이너의 안정성 계약도 주 트레이너와 구분한다.

VLM이나 도구 사용은 입력 형식·채팅 템플릿·모델 지원 조건을 따른다. 동일한 코드가 모든 모델과 수백 GPU에서 그대로 작동한다고 가정하지 않는다.

## ROLL

[ROLL](https://github.com/alibaba/ROLL)은 `Reinforcement Learning Optimization for Large-scale Learning`의 약자다. 단일 제어기, 병렬 worker 추상화, rollout scheduler, 환경·보상 worker를 제공한다. 원 논문은 `arXiv:2506.06122`다.

자원 매핑과 다양한 학습·상호작용 파이프라인을 조율하는 라이브러리다. 자동 보상 정규화가 보상 해킹을 해결하거나 운영 서비스에서 계속 학습하기에 항상 적합하다는 보장은 없다.

## 선택할 때 비교할 항목

| 프레임워크 | 공식 설계의 중심 | 재현 전 확인 |
|------------|------------------|--------------|
| OpenRLHF | Ray·vLLM·DeepSpeed와 agent 실행기 | advantage·실행 모드·구성 키 |
| verl | HybridFlow와 통합 V1 trainer | 모델 engine·롤아웃·비동기 버전 |
| TRL | Hugging Face 트레이너 | 안정·실험 API와 제거된 기능 |
| ROLL | 제어기·worker·롤아웃 조율 | 학습 파이프라인·자원 매핑 |

모델 크기만으로 도구를 결정하지 않는다. 필요한 알고리즘과 지원 모델의 작은 실행을 먼저 확인한다. 이후 같은 토큰 예산에서 처리량·메모리·정확도·실패 복구를 비교한다.
