## GRPO 이후에 무엇을 바꾸는가

원 GRPO는 [그룹](../../01-rl-fundamentals/00-notation/#grpo) 보상으로 advantage를 계산하고, 응답별 토큰 평균을 사용한다. 후속 방법은 클리핑, 배치 구성, 보상 스케일링, 길이 집계를 각각 수정한다. 한 항만 바꾸고 전체 알고리즘을 재현했다고 부르면 안 된다.

## DAPO의 네 가지 기법

DAPO의 네 기법은 Clip-Higher, Dynamic Sampling, Token-Level Policy Gradient Loss, Overlong Reward Shaping이다. KL 제거는 논문의 사전 설계 선택이며 네 번째 기법은 아니다.

### Clip-Higher

[PPO 확률비](../../01-rl-fundamentals/00-notation/#ppo)의 상·하 클립 폭을 독립적으로 둔다.

$$
\ell_{i,t}=\min\left(\rho_{i,t}\hat A_i,\operatorname{clip}(\rho_{i,t},1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}})\hat A_i\right)
$$

> **직관.** 양의 advantage는 상한에서, 음의 advantage는 하한에서 개선 유인이 잘린다. 음의 advantage에서도 `min`을 쓰며, 부호가 음수이므로 확률비의 하한 클리핑이 작동한다. 이 식의 역할은 개선 유인을 자르는 것이며 확률비 자체를 강제하지는 않는다.

논문의 예시 설정은 하한 폭 0.20, 상한 폭 0.28이다. 상한 폭을 늘리면 좋은 저확률 토큰을 더 강화할 여지가 생긴다. 이 값이 모든 모델에서 최적이라는 뜻은 아니다.

### Dynamic Sampling

정답·오답이 섞인 그룹만 남기고, 추가 프롬프트에서 응답을 샘플링하여 유효 배치를 채운다. 동점 그룹의 advantage는 수치 안정화 후 모두 0이므로 정책 기울기 신호가 없다. 단순히 작은 배치로 업데이트하는 것과 다르다. 모든 후보가 동점이면 재샘플링 비용이 늘어나므로 유효 그룹 비율도 기록한다.

### Token-Level Policy Gradient Loss

$$
L_{\text{DAPO}}=-\frac{\sum_i\sum_{t=1}^{|y_i|}\ell_{i,t}}{\sum_i|y_i|}
$$

> **직관.** 응답별 평균 대신 배치의 유효 토큰 수로 나눈다. 같은 배치 안에서 토큰마다 같은 집계 가중치를 주지만, 배치 길이에 따른 정규화까지 없애지는 않는다는 의미다.

### Overlong Reward Shaping

길이 한도 때문에 잘린 응답을 내용 오답과 무조건 동일하게 처리하면 보상 잡음이 생긴다. DAPO는 잘린 표본의 처리와 한도 근처의 완만한 길이 벌점을 다룬다. 생성 길이, 절단 마스크, 실제 정답 여부를 따로 기록한다.

DAPO는 실험에서 참조 [KL](../../01-rl-fundamentals/00-notation/#divergences) 항도 제거했다. 이는 특정 추론 학습 설정의 선택이다. 클리핑이 KL 제약과 동치이거나, KL 제거가 일반적으로 수렴을 보장한다는 뜻은 아니다.

### 집계와 클리핑의 실행 예제

아래는 이미 생성한 롤아웃의 토큰 로그 확률과 마스크를 받는 교육용 손실이다. 동적 샘플링·보상 계산·분산 집계·최적화 루프는 포함하지 않는다. 최소 한 개의 유효 토큰이 있다고 가정한다.

```python
import torch


def dapo_loss(new_logps, old_logps, advantages, mask,
              eps_low=0.20, eps_high=0.28):
    # Shape: log probabilities and mask [batch, tokens], advantages [batch].
    ratio = torch.exp(new_logps - old_logps.detach())
    advantage = advantages.detach().unsqueeze(-1)
    clipped_ratio = ratio.clamp(1 - eps_low, 1 + eps_high)
    surrogate = torch.minimum(ratio * advantage, clipped_ratio * advantage)
    return -(surrogate * mask).sum() / mask.sum()
```

새 로그 확률은 반드시 프롬프트와 이전 응답 토큰으로 조건화한다. padding·사용자 메시지·도구 관측 토큰은 정책 손실에서 제외한다. 분산 학습에서는 로컬 토큰 수와 전역 누적 배치의 토큰 수가 다른 점도 처리해야 한다.

## Dr. GRPO: 길이·난이도 정규화 수정

Dr. GRPO는 표준편차 추정의 자유도를 보정하는 방법이 아니다. 응답 길이로 나누는 항과 그룹 표준편차로 나누는 항을 제거한다.

$$
\tilde A_i=r_i-\bar r,\qquad
L_{\text{Dr. GRPO}}=-\frac{1}{GC}\sum_i\sum_{t=1}^{|y_i|}\ell_{i,t}(\tilde A_i)
$$

> **직관.** 그룹 평균은 빼되 표준편차로 문제별 학습 가중치를 바꾸지 않는다. $C$는 최대 생성 길이 같은 고정 상수다. 고정 분모는 길이에 따른 가중치 변화를 줄이는 역할을 한다. 응답 길이나 현재 배치 길이를 분모로 쓰지 않는다.

원 GRPO의 길이 정규화는 양의 advantage에서 짧은 응답의 토큰을, 음의 advantage에서 긴 응답의 토큰을 상대적으로 다르게 가중한다. 표준편차 정규화는 그룹 보상 분포에 따라 문제별 가중치를 바꾼다. Dr. GRPO의 수정은 이 두 편향을 겨냥하며, 모든 보상·모델의 최적성을 보장하지 않는다.

| 설계 | 원 GRPO | DAPO | Dr. GRPO |
|------|---------|------|----------|
| 손실 분모 | 응답 길이 후 그룹 평균 | 유효 토큰 합 | 고정 상수 × 그룹 크기 |
| 그룹 표준편차 나눗셈 | 사용 | 사용 | 제거 |
| 클리핑 | 대칭 | 비대칭 | 원 PPO 형태 |
| 동점 그룹 교체 | 핵심 기법 아님 | 사용 | 핵심 기법 아님 |

## REINFORCE++와 GSPO

REINFORCE++는 critic 없는 정책 최적화에 전역 advantage 정규화 등을 결합한다. 미니배치마다 따로 정규화하는 것과 전체 롤아웃 배치에서 정규화하는 것을 구분한다. KL 항의 포함 여부도 구현의 독립 선택이다.

GSPO는 응답 전체 가능도 비율에 길이의 역수를 지수로 적용한다.

$$
s_i=\left(\frac{\pi_\theta(y_i\mid x)}{\pi_{\theta_{\text{old}}}(y_i\mid x)}\right)^{1/|y_i|}
=\exp\left(\frac{1}{|y_i|}\sum_t\log\rho_{i,t}\right)
$$

> **직관.** 토큰 비율의 기하평균으로 응답 전체의 업데이트를 판단한다. 단순한 시퀀스 확률비와 다르며, 시퀀스 수준 클리핑은 응답 전체의 갱신을 결정하며 토큰 수준 클리핑과 같은 연산이 아니다.

GSPO 논문은 특히 MoE 훈련의 안정성을 연구한다. 성능 비교에서는 모델·보상·롤아웃 예산·추론 엔진을 함께 고정한다.

## 현재 TRL 구현과 논문을 대응하기

2026년 10월 23일 확인한 [TRL GRPO 문서](https://huggingface.co/docs/trl/grpo_trainer)에서는 기본 손실이 `dapo`, 기본 `beta`가 0이다. `GRPOTrainer`라는 이름만으로 원 GRPO의 길이 집계와 KL 항을 가정하면 안 된다.

`loss_type="dr_grpo"`는 손실 분모를 바꾼다. 논문의 표준편차 제거까지 대응하려면 `scale_rewards="none"`도 별도로 지정한다. 다음은 전체 훈련 스크립트가 아니라 구성 예제다. 설치 버전의 `GRPOConfig` 지원 항목을 먼저 확인한다.

```python
from trl import GRPOConfig

args = GRPOConfig(
    output_dir="dr-grpo-run",
    loss_type="dr_grpo",
    scale_rewards="none",
    beta=0.0,
    num_generations=8,
    max_completion_length=1024,
)
```

손실·보상 스케일링·KL·절단 처리·클립 폭을 실험 기록에 모두 남긴다. DAPO 손실만 선택했다고 동적 샘플링과 긴 응답의 보상 처리까지 재현되는 것은 아니다.
