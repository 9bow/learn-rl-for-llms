## 결과와 과정 보상

결과 보상 모델(ORM)은 완성된 응답을 평가한다. 과정 보상 모델(PRM)은 풀이의 중간 단계에 점수를 준다. ORM이 반드시 마지막 숫자만 보거나 0/1 점수만 내는 것은 아니다.

```text
ORM: 전체 풀이 → 결과 점수
PRM: 단계 1 → 단계 2 → 단계 3 → 단계별 판정
실행 검증기: 최종 답·테스트·형식 증명을 명시적 규칙으로 검사
```

PRM은 오류 위치를 추정하여 후보 선택과 학습에 도움을 줄 수 있다. 그러나 학습된 판정이므로 단계 정확성을 보장하지 않는다. 결과 보상만 써도 정책 경사는 개별 행동의 기여를 추정할 수 있으므로, 모든 단계에 같은 벌점을 준다는 설명도 정확하지 않다.

## 단계 점수의 집계

단계 점수의 합, 최솟값, 곱은 서로 다른 후보 순위를 만든다. 점수를 더하면 불필요하게 단계를 늘리는 응답이 유리해질 수 있다. 어떤 집계가 논문·구현에 쓰이는지 명시한다.

$$R_{\text{sum}}(x,y)=\sum_{k=1}^{K}r_k(x,y_{1:k})$$

위 식은 가능한 합산 설계의 예시이며 모든 PRM의 기본 목적식이 아니다. 단계 경계와 종료 처리를 함께 정해야 한다.

## 인간 주석과 PRM800K

[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)은 수학 풀이 단계의 인간 피드백을 이용한 과정 감독을 평가하고 PRM800K를 공개한다. 약 800K는 완성 풀이 수가 아니라 단계 레이블 수다.

이 연구의 결과는 지정된 생성기·검증기·MATH 평가 설정에서 해석해야 한다. "MATH 90%에 PRM 100개, ORM 400개"처럼 근거가 확인되지 않는 공통 표본 수로 바꾸어 제시하지 않는다.

## Monte Carlo 완성과 Math-Shepherd

[Math-Shepherd](https://arxiv.org/abs/2312.08935)는 중간 풀이에서 여러 번 이어 풀어 최종 성공 신호를 얻는 자동 과정 감독을 연구한다. 성공 비율은 해당 완성 정책의 후속 성공 가능성에 대한 추정이다.

$$\hat v(y_{1:k})=\frac{\text{정답으로 끝난 후속 완성 수}}{\text{후속 완성 시도 수}}$$

이 값이 낮다고 현재 단계가 논리적으로 틀렸다고 단정할 수 없다. 후속 모델이 어려운 나머지를 풀지 못할 수도 있다. 완성 예산과 표본 오차도 고려한다.

## ThinkPRM과 생성적 검증

[ThinkPRM](https://arxiv.org/abs/2504.16828)은 단계 판정을 위한 검증 추론을 생성한다. 수학 과정 감독을 중심으로 학습하고, 후보 선택·검색과 일부 분포 외 문제를 평가한다. 긴 설명을 생성한다고 판정의 정확성이 자동 보장되지는 않는다.

## 적용 전 확인

| 항목 | 구분 |
|------|------|
| 감독 자료 | 인간 단계 레이블·후속 완성·모델 판정 |
| 사용 위치 | 정책 학습·보상·가치 초기화·추론 시 선택 |
| 집계 | 합·최솟값·곱·검증된 별도 기준 |
| 평가 | 오류 탐지·후보 선택·실제 최종 성공률 |

과정 감독과 결과 검증을 함께 사용하고, 같은 토큰 예산에서 효율을 비교한다. 검증기의 학습 자료와 평가 문제가 섞이지 않도록 분할한다.
