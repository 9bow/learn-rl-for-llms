## 자기 생성 데이터는 보상이 아니다

멀티모달 모델은 이미지·화면·도구 결과를 보며 여러 행동을 합니다. 모델이 만든 고보상 궤적을 다시 학습 데이터로 쓰는 자기 개선은 유용할 수 있지만, “모델이 골랐으니 정답”이라고 가정하면 오류를 증폭시킵니다. 자기 생성 결과는 독립적인 검증기, 사람 검토 또는 실행 결과가 있을 때만 학습 신호가 됩니다.

```text
화면 관찰 → 행동 후보 여러 개 생성 → 환경 실행
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
             성공 상태 확인                        실패 원인 기록
                    │                                   │
                    └──────── 검증된 궤적만 선별 ────────┘
                                      │
                                      ▼
                              다음 학습 라운드
```

## 과정 보상은 화면 변화와 연결돼야 한다

텍스트 추론의 PRM은 중간 문장을 점검합니다. 컴퓨터 사용에서는 “버튼을 눌렀다”는 문장보다 실제 화면·파일·애플리케이션 상태 변화가 더 직접적인 근거입니다. 과정 보상은 다음 질문을 확인해야 합니다.

| 단계 | 가능한 관찰 | 잘못된 보상 예 |
| --- | --- | --- |
| 화면 읽기 | 대상 요소가 실제로 보이는가 | 설명만 그럴듯한 경우 |
| 행동 | 클릭·입력이 유효했는가 | 좌표만 맞춘 경우 |
| 중간 상태 | 다음 단계가 가능한 상태인가 | 우연히 비슷한 화면이 된 경우 |
| 완료 | 파일·폼·앱 상태가 요구를 만족하는가 | 성공 메시지만 흉내 낸 경우 |

## OSWorld와 실행 기반 평가

[OSWorld](https://github.com/xlang-ai/OSWorld)는 실제 웹·데스크톱 애플리케이션을 포함한 컴퓨터 작업에서 에이전트를 평가하도록 설계된 환경입니다. 화면 스크린샷만으로 점수를 주지 않고, 초기 상태 설정과 최종 상태 검증을 함께 둡니다. 이런 구조는 시각 언어 모델의 “보았다”는 주장과 실제 작업 완료를 구분하게 합니다.

컴퓨터 사용 RL에서는 실행을 격리해야 합니다. 네트워크, 계정, 파일 쓰기, 시간 제한을 명시하지 않으면 학습 과정에서 위험하거나 재현 불가능한 행동이 보상될 수 있습니다. 되돌릴 수 없는 행동은 별도 승인 상태로 모델링하는 편이 안전합니다.

## 정리

자기 증류·과정 보상·컴퓨터 사용은 모두 더 많은 궤적을 쓰려는 방법이지만, 공통 기반은 독립적인 환경 검증입니다. 멀티모달 RL은 텍스트 설명의 그럴듯함이 아니라 관찰 가능한 상태 전이와 최종 결과를 보상해야 합니다.
