## 시각 태스크의 검증 가능한 보상

시각 RLVR은 이미지와 질문을 입력으로 받아, 출력의 정답을 정해진 규칙으로 평가한다. 보상 계산을 자동화해도 정답 레이블·박스·문자열 등의 데이터가 필요할 수 있다. 인간 주석이 전혀 필요 없다는 뜻은 아니다.

| 태스크 | 검증 자료 | 보상 설계 예시 |
|--------|-----------|----------------|
| 객체 위치 | 정답 바운딩 박스 | IoU |
| OCR | 정답 문자열 | 편집 거리 기반 점수 |
| VQA·계수 | 정답 레이블·숫자 | 파싱 후 일치 여부 |
| 공간 관계 | 주석 또는 환경 상태 | 관계 조건 충족 여부 |

위 표는 설계 예시이며 특정 논문의 검증된 기본 하이퍼파라미터 표가 아니다.

## IoU 보상

두 박스의 교집합 면적을 합집합 면적으로 나누면 IoU를 얻는다.

$$\operatorname{IoU}(\hat b,b^*)=\frac{|\hat b\cap b^*|}{|\hat b\cup b^*|}$$

단일 객체 예제에서는 클래스가 맞을 때 IoU를 보상으로 쓸 수 있다. 다중 객체에서는 정답과 예측의 매칭, 누락, 중복, 잘못된 박스도 처리해야 한다. IoU 하나가 탐지 정밀도나 전체 mAP와 같은 지표는 아니다.

## VLM에 GRPO 적용

[Hugging Face의 VLM GRPO 레시피](https://huggingface.co/learn/cookbook/en/fine_tuning_vlm_grpo_trl)는 이미지·텍스트 입력에서 여러 답을 만들고, 보상 함수를 적용하는 예를 제공한다. 이미지 전처리와 채팅 템플릿은 모델의 processor를 따른다.

현재 [TRL GRPO 문서](https://huggingface.co/docs/trl/grpo_trainer)는 지원 VLM과 입력 형식을 설명한다. 일반 문자열 completion과 대화형 메시지 completion의 모양이 다르므로 보상 함수도 맞춰야 한다. 이미지 픽셀 제한과 생성 길이를 실제 메모리 조건에 맞게 설정한다.

모든 VLM 구성요소를 반드시 학습하는 것은 아니다. 시각 인코더·프로젝터·언어 모델 중 학습 대상을 명시하고, 이미지 토큰과 출력 토큰의 마스크를 구분한다.

## RLVR-World와의 구분

[RLVR-World](https://github.com/thuml/RLVR-World)는 세계 모델의 생성 품질을 검증 가능한 보상으로 개선하는 연구다. 단일 에이전트를 텍스트 게임·웹 탐색·로봇 제어 세 환경에서 동시에 훈련한다는 의미가 아니다. 세계 모델 학습과 그 모델 안에서 행동하는 정책 학습을 구분한다.

## 검증기의 한계

정답 숫자만 맞아도 이미지 근거를 무시하는 모델이 높은 점수를 받을 수 있다. 이미지 교체·가림·질문 변형 평가로 시각 정보에 실제로 의존하는지 살핀다. OCR 정규화는 의미 있는 기호나 단위를 지우지 않도록 설계한다.

위성·의료 이미지에서는 해당 분야의 검증 자료와 평가가 필요하다. 일반 사진의 레시피나 임의의 학습 스텝 수를 그대로 최적 구성으로 제시할 수 없다.
