## DPO의 한계

DPO는 단순하고 효과적이지만 몇 가지 구조적 한계를 가집니다. 첫째, 유한한 선호 표본을 반복 최적화하면 선호 마진을 과도하게 키우고 평가 성능이 악화되는 **과적합**이 발생할 수 있습니다. 둘째, 쌍대 비교(pairwise comparison) 데이터가 필수이므로 수집 비용이 높습니다. 셋째, 참조 모델을 항상 유지해야 하므로 메모리 비효율이 발생합니다. 이러한 문제를 각자의 방식으로 해결한 변형들이 등장했다.

---

## IPO: Identity Preference Optimization

**IPO** (Azar et al., 2024)는 DPO의 이론적 취약점을 분석하고 이를 수정한 방법입니다. 결정적인 선호 표본을 분류하는 DPO의 로지스틱 손실은 로그 비율 마진을 계속 키워 낮출 수 있습니다. 큰 마진에서는 그래디언트도 작아지지만, 유한한 목표 마진을 직접 지정하지 않는다는 점이 핵심입니다. 이를 모든 DPO 학습이 반드시 과적합한다는 뜻으로 해석하지 않습니다.

IPO는 [학습 정책 π\_θ](../../01-rl-fundamentals/00-notation/#policies)와 [참조 정책 π\_ref](../../01-rl-fundamentals/00-notation/#policies), [선호/비선호 쌍](../../01-rl-fundamentals/00-notation/#dpo) 위에서 시그모이드 링크 함수를 제거하고 직접적인 회귀 목표를 사용합니다.

$$
L_{\text{IPO}}(\pi_\theta; \pi_{\text{ref}}) = \mathbb{E}_{(x, y_w, y_l)}\!\left[\left(\log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} - \frac{1}{2\beta}\right)^2\right]
$$

> **직관.** DPO의 시그모이드 포화 문제를 해결한다 — 로그 비율 마진이 과도하게 커지지 않도록 회귀 손실로 바꾼다. DPO는 마진이 이미 크면 그래디언트가 0에 가깝게 줄어들어 규제가 풀리는데, IPO는 마진을 [\\(\beta\\)](../../01-rl-fundamentals/00-notation/#dpo)로 결정되는 목표값 $\frac{1}{2\beta}$ 근처로 계속 끌어당겨 과적합을 막는 역할을 한다.

이 손실은 **정책 비율 차이를 $\frac{1}{2\beta}$에 근사** 시키는 회귀 문제로, 과적합 시에도 그래디언트가 계속 존재해 규제(regularization) 효과를 유지합니다.

## KTO: Kahneman-Tversky Optimization

**KTO** (Ethayarajh et al., 2024)는 쌍대 비교 데이터 대신 **이진 피드백(binary feedback)** 만으로 학습하는 방법입니다. 각 응답에 대해 "좋다(desirable)" 또는 "나쁘다(undesirable)"라는 단순한 레이블만 있으면 됩니다. 이는 실제 데이터 수집 환경에서 훨씬 자연스럽다.

KTO의 이론적 기반은 **Kahneman-Tversky 전망 이론(Prospect Theory)** 입니다. 인간은 이득(gain)보다 손실(loss)에 더 민감하게 반응하는 비대칭적 효용 함수를 가진다는 이론으로, 노벨 경제학상을 받은 심리학적 발견입니다.

$$
L_{\text{KTO}}(\pi_\theta; \pi_{\text{ref}}) = \mathbb{E}_{(x, y)}\bigl[w(y)\bigl(\mathbf{1} - v_{\text{KTO}}(\pi_\theta, \pi_{\text{ref}}, x, y)\bigr)\bigr]
$$

> **직관.** 선호 쌍 대신 이진 신호로 학습한다. 사람의 비대칭 선호를 모델링할 수 있으며, $w(y)$가 "좋다/나쁘다" 레이블별로 가중치를 바꿔 손실 회피 성향을 재현한다. 쌍대 비교 데이터 수집이 비싼 상황에서 이진 피드백만으로도 [\\(\sigma\\)](../../01-rl-fundamentals/00-notation/#dpo) 기반 효용을 학습할 수 있다는 의미다.

여기서 $v_{\text{KTO}}$는 참조 대비 로그 확률 비율을 기준점과 비교해 시그모이드로 변환한 효용값이며, $w(y)$는 레이블별 가중치입니다. 불호 가중치가 반드시 더 커야 하는 것은 아니며 데이터 불균형에 맞춰 조정합니다. $z_{\text{ref}}$는 정책과 참조의 KL에서 얻는 기준점으로, 개별 응답 자체가 KL 값인 것은 아닙니다. 논문은 여러 설정에서 DPO와 경쟁력 있는 결과를 보고하지만 일반적인 우열을 보장하지 않습니다.

## ORPO: Odds-Ratio Preference Optimization

**ORPO** (Hong et al., 2024)는 참조 모델을 완전히 제거하는 동시에 SFT(Supervised Fine-Tuning)와 선호 최적화를 **단일 학습 단계** 로 통합합니다.

ORPO의 핵심은 **오즈 비(Odds Ratio)** 를 이용한 선호 신호 계산입니다. 원 논문은 일반적인 시퀀스 확률 대신 평균 토큰 로그 확률을 지수화한 $\bar p_\theta(y|x)=\exp(\log\pi_\theta(y|x)/|y|)$를 사용합니다. 아래 오즈와 SFT 항에도 이 길이 정규화 값을 사용합니다.

$$
\operatorname{odds}_\theta(y|x) = \frac{\bar p_\theta(y|x)}{1 - \bar p_\theta(y|x)}
$$

> **직관.** 길이 정규화 점수를 오즈 형태로 변환해 두 응답을 비교합니다. $\bar p$는 전체 응답에 대해 합이 1인 분포가 아니므로 이 값을 실제 시퀀스가 발생할 확률로 해석하지 않습니다. 구현에서는 평균 로그 확률과 안정적인 `log1mexp` 계산을 사용해 로그 오즈를 구합니다.

$$
L_{\text{ORPO}} = \mathbb{E}\!\left[-\log \bar p_\theta(y_w|x) - \lambda \log \sigma\!\left(\log \frac{\operatorname{odds}_\theta(y_w|x)}{\operatorname{odds}_\theta(y_l|x)}\right)\right]
$$

> **직관.** SFT와 선호 학습을 한 단계로 합친다. [선호된 응답 y\_w](../../01-rl-fundamentals/00-notation/#dpo)의 log-odds가 [비선호 y\_l](../../01-rl-fundamentals/00-notation/#dpo) 대비 높아지도록 직접 밀어주는 역할을 하며, 앞 항의 표준 SFT 우도와 뒤 항의 오즈비 마진이 하나의 그래디언트로 통합된다. 참조 모델 없이도 정렬이 가능해지는 의미가 있다.

첫 번째 항은 표준 SFT 손실이고, 두 번째 항은 오즈 비 기반 선호 정렬 손실입니다. 참조 모델의 추론·메모리는 필요 없지만 정책 학습의 옵티마이저·활성화 메모리는 남습니다. 별도 SFT와 선호 단계를 합친 원 논문은 Phi-2, Llama-2, Mistral 등에서 평가했습니다. 이를 모든 기반 모델에서 DPO보다 우수하다는 주장으로 일반화하지 않습니다.

## 종합 비교

| 기준 | DPO | IPO | KTO | ORPO |
|------|-----|-----|-----|------|
| 데이터 형식 | 쌍대 (win/lose) | 쌍대 (win/lose) | 이진 (good/bad) | 쌍대 (win/lose) |
| 참조 모델 | 필요 | 필요 | 필요 | **불필요** |
| SFT 단계 | 별도 필요 | 별도 필요 | 별도 필요 | **통합** |
| 마진 제어 | 로지스틱 손실 | 유한한 목표 마진 회귀 | 기준점 대비 효용 | 오즈 비 선호 손실 |
| 이론적 기반 | BT + MLE | 직접 회귀 | 전망 이론 | 오즈 비 |
| 구현 복잡도 | 낮음 | 낮음 | 낮음 | 낮음 |
| 쌍대 비교 필요 여부 | 필요 | 필요 | **불필요** | 필요 |

각 방법은 서로 다른 실용적 제약을 해결합니다. 쌍대 데이터 수집이 어려우면 KTO, 메모리 효율이 중요하면 ORPO, 과적합 제어가 필요하면 IPO가 적합하다. 실제 응용에서는 데이터 가용성과 컴퓨팅 자원에 따라 알고리즘을 선택합니다.
