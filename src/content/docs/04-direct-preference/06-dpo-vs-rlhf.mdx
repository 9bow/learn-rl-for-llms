## 비교의 전제

DPO와 PPO는 알고리즘이고, RLHF는 인간 피드백을 이용하는 학습 절차다. 이 장에서는 고정 선호 쌍을 사용하는 원 DPO와, 학습된 보상 모델을 사용하는 온라인 PPO-RLHF를 비교한다. DPO도 인간 선호를 사용할 수 있다.

## 데이터 수집과 탐색

원 DPO는 고정된 `(prompt, chosen, rejected)` 데이터를 학습하며 업데이트 중 새 응답을 생성하지 않는다. 정책은 주어진 쌍의 상대적 가능도를 조정한다. 데이터에 없는 응답을 절대 생성할 수 없다는 뜻은 아니다.

PPO-RLHF는 현재 정책으로 응답을 생성하고 보상 모델로 평가한다. 새로운 응답을 탐색할 수 있지만, 보상 모델의 학습 분포에서 멀어진 응답에는 잘못된 점수를 줄 수 있다. 온라인 샘플링이 모든 분포 이동 문제를 제거하지는 않는다.

## 계산 구성

| 항목 | 원 DPO | 전형적인 PPO-RLHF |
|------|--------|------------------|
| 입력 | 선호 응답 쌍 | 프롬프트와 롤아웃 |
| 보상 모델 | 별도 학습 불필요 | 응답 점수 계산 |
| 가치 모델 | 불필요 | advantage 추정 |
| 참조 정책 | 로그 확률 비교 | KL 기준 |
| 롤아웃 | 업데이트 중 불필요 | 반복 생성 |
| 주요 비용 | 정책 학습·참조 점수 | 생성·보상·정책·가치 학습 |

DPO는 참조 로그 확률을 미리 계산하거나 어댑터를 공유할 수 있다. PPO도 모델 배치·오프로딩·파라미터 공유에 따라 메모리가 달라진다. 모델 역할의 수를 실제 GPU 복제본 수나 총 메모리와 동일시하지 않는다.

## 성능과 안정성을 비교하는 방법

DPO 원 논문은 감성 제어·요약·대화에서 경쟁력 있는 결과를 보고한다. 이것이 모든 단순 과제에서의 우위를 뜻하지는 않는다. 온라인 정책 최적화는 탐색이 필요한 문제에 유용하지만, 추론 모델의 성공만으로 PPO가 DPO보다 항상 낫다고 결론 낼 수도 없다.

비교 시 SFT 시작점, 선호 데이터, 보상 모델, 생성·학습 토큰 예산, 평가 판정자를 고정한다. 학습 손실, 보상 점수, 실제 성공률을 구분한다. 두 방법 모두 길이 편향·데이터 오류·대리 목표 과최적화에 취약하다.

## 반복적 선호 최적화

Online DPO나 Iterative DPO는 현재 정책의 응답을 새로 생성하고, 인간·보상 모델·AI 판정자로 선호를 얻은 뒤 업데이트한다. 별도의 학습된 보상 모델이 항상 필요한 것은 아니지만, 비교 피드백의 출처는 반드시 필요하다.

[RLHF Workflow](https://arxiv.org/abs/2405.07863)는 보상 모델과 온라인 학습을 함께 비교하는 실제 연구 사례다. 그 논문의 특정 데이터·모델 결과를 모든 DPO→PPO 전환의 보장으로 읽지 않는다.

## 선택 기준

고품질 선호 쌍이 있고 롤아웃 비용이 제한되면 DPO로 시작할 수 있다. 실행 가능한 검증기나 새 상호작용이 필요하면 온라인 정책 최적화를 검토한다. 이후 같은 평가 세트와 예산에서 결과를 비교하여 선택한다.
