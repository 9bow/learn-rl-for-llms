## 도구 선택과 호출 시점

도구 사용 정책은 어떤 도구를, 언제, 어떤 인자로 호출할지 결정한다. 코드 실행·검색·계산기 등의 반환값은 다음 행동의 관측이 된다. 호출 성공 상태 코드와 사용자의 최종 목표 달성은 별개다.

어느 문제가 더 중요하다고 일반 순위를 매기기보다, 과제별로 도구 선택·시점·인자 오류를 분리해 평가한다.

## ReTool

[ReTool](https://arxiv.org/abs/2504.11536)은 자연어 추론과 실시간 코드 실행을 번갈아 사용하는 전략을 학습한다. 합성 cold-start 데이터로 먼저 미세조정한 뒤, 실제 코드 실행이 포함된 멀티턴 롤아웃과 최종 결과 보상으로 RL을 수행한다.

논문의 32B 실험은 AIME에서 400 학습 스텝 후 67%를 보고하고, 비교한 텍스트 RL 기준선은 1,080스텝 후 40%를 보고한다. 이는 해당 실험의 결과다. 도구 계산 비용·생성 예산이 다른 일반 언어 모델과의 공정한 비용 비교를 자동으로 뜻하지 않는다.

ReTool의 보상을 임의의 "불필요한 호출 수 × 벌점" 수식으로 바꾸면 원 논문의 알고리즘을 재현한 것이 아니다. 비용 벌점은 별도의 설계 선택으로 평가해야 한다.

## RL-Factory

[공식 RL-Factory 저장소](https://github.com/Simple-Efficient/RL-Factory)는 멀티턴 도구 사용 RL과 환경 연결을 지원한다. 튜토리얼은 Search-R1 재현을 예제로 사용한다. 특정 arXiv 식별자가 아니라 저장소의 실제 문서·예제를 기준으로 설치와 구성을 확인한다.

도구 정의·환경 실행·보상·학습기의 경계를 확인한다. 임의의 YAML 도구 정의만 있으면 모든 API를 자동 학습할 수 있다고 가정하지 않는다.

## 도구 출력과 정책 토큰

```text
사용자 질문 → 정책의 도구 호출 → 환경 실행
환경 결과 → 정책의 해석·다음 호출 → 최종 답
최종 상태 검사 → 롤아웃 보상 → 정책 업데이트
```

도구 결과는 정책이 생성한 행동이 아니다. 결과 토큰을 정책 손실에 포함하지 않고, 정책이 만든 호출·인자·응답 토큰에만 손실을 적용한다. 프롬프트·호출·도구 반환값·롤아웃 로그 확률을 함께 저장해야 학습 추적을 재구성할 수 있다.

## 보상과 실행 경계

| 관측 | 직접 알 수 있는 것 | 추가 검사 |
|------|------------------|-----------|
| JSON 파싱 성공 | 형식이 유효함 | 실제 도구 이름·인자·권한 |
| HTTP 200 | 요청 처리가 성공 응답을 반환함 | 데이터·최종 상태의 정확성 |
| 코드 실행 성공 | 예외 없이 실행함 | 비공개 테스트·자원 제한 |
| 호출 횟수 감소 | 도구 비용이 줄어듦 | 실제 성공률 유지 |

형식 보상만 높이면 무의미한 유효 호출을 반복할 수 있다. 가능하면 최종 환경 상태를 검사하고, 중간 보상은 별도 실험으로 추가한다. 비용·지연·성공률을 동시에 기록한다.

훈련 환경에서 코드를 실행할 때도 파일·네트워크·자원 권한은 실행기가 제한한다. 높은 보상이나 자연어 지시는 권한을 새로 부여하지 않는다. 테스트와 환경 이미지를 고정하고 평가용 비밀을 롤아웃 입력에 넣지 않는다.

## Toolformer와의 구분

[Toolformer](https://arxiv.org/abs/2302.04761)는 모델이 생성한 API 호출을 언어 모델링 손실 개선으로 필터링하는 자기지도 접근이다. 도구를 사용한다는 공통점만으로 ReTool과 같은 온라인 RL 방법으로 분류하지 않는다.
